# Wiring on Opencode

## Role subagents

One agent file per role, at `~/.config/opencode/agents/tdd-{red,green,refactor}.md`.
Opencode frontmatter differs from Claude Code — there is no `tools:`,
`maxTurns:`, or per-agent `hooks:` block. Use `mode: subagent` so the
agent can only be invoked as a sub-task, plus optional `permission:` to
tighten tool access.

Template: `assets/opencode-agent-template.md`. Green and Refactor use the
same shape as the template.

> Duplication note: the role body is copied verbatim from
> `skills/tdd/references/roles/*.md`. This could be generated by Nix /
> home-manager so the skill's reference file remains the single source of
> truth. Manual sync until then.

## Slash command

`~/.config/opencode/commands/tdd.md` (or a symlink into this skill's
SKILL.md — Opencode reads the markdown body as the prompt template, so a
symlink keeps both surfaces in sync).

Opencode supports `$ARGUMENTS`, `$1`, `$2`, `$3` in command bodies. The
`argument-hint` Claude Code field is not recognised — omit it or move the
hint into the description.

## Guard plugin

Opencode has no shell-based hook system; guards are TypeScript plugins.
The reference implementation lives at
`skills/tdd/assets/opencode-tdd-guard.ts`. Install to
`~/.config/opencode/plugin/tdd-guard.ts`.

The plugin listens on `tool.execute.before`, reads the current phase from
`.tdd/phase` (written by the orchestrator on each phase transition —
`red`, `green`, or `refactor`), and throws when the tool call would write
to a path the phase disallows. A missing `.tdd/phase` file disables
enforcement, matching the no-guard degradation path.

## Orchestrator responsibilities on Opencode

Because the plugin reads phase state from disk rather than being invoked
with a mode argument, the orchestrator must:

1. Write `red`, `green`, or `refactor` to `.tdd/phase` at each phase
   transition (before delegating to the role).
2. Delete `.tdd/phase` at wrap-up so unrelated writes outside a TDD loop
   are not blocked.

## Verification

At session start, the orchestrator checks that
`~/.config/opencode/plugin/tdd-guard.ts` exists. If missing, warn the
user and proceed under prompt-only enforcement (see `references/guard.md`).
